Large Language Model

How the LLM Thinks

TalentLens uses Llama-3.1-8B-Instruct (or Llama-3.1-8B-Instruct) via HuggingFace to generate interview questions, evaluate answers, and produce reports. Here's exactly how it works.

What is an LLM?

A Large Language Model is a neural network trained on billions of text documents. It learns to predict the next most likely token (word fragment) given everything before it.

TalentLens sends a carefully crafted prompt (containing the resume + rules) to the model, which then generates a response one token at a time. 

// Actual prompt structure sent by TalentLens

SYSTEM: You are a technical interviewer
for the role: "Frontend Developer".

CANDIDATE RESUME:
  Skills: React, TypeScript, CSS
  Projects: "Finance Tracker"
  Experience: BrightUI Studio

RULES:
1. Use EXACT names from resume
2. One focused question only
3. Output ONLY the question

USER: Generate question 3 of 10.

ASSISTANT: ▋ ← model generates here
Step 1 — Tokenisation

Text is split into tokens (word pieces). The model never sees raw text — only numbers representing tokens.

💡 Common words = 1 token. Rare words split into pieces. "Finance" → "Fin" + "ance"

Step 2 — Self-Attention (How the model "reads")

Each token attends to every other token. Brighter = stronger attention. This is how the model knows "Finance Tracker" refers to a specific project.

Step 3 — Next Token Prediction

The model outputs a probability distribution over all ~32,000 tokens. It picks the most likely next token, appends it, and repeats.

How TalentLens Uses the LLM
1

Question Generation (temp 0.55)

Resume + rules → model generates ONE targeted question about a specific company/project/skill. Low temperature = focused, not random.

2

Answer Evaluation (temp 0.3)

Question + candidate answer → model returns JSON with score 1-10, feedback, strengths, improvements. Very low temperature = consistent scoring.

3

Follow-up Generation (temp 0.6)

Previous Q + candidate's exact answer → model probes deeper into something specific the candidate said. Medium temp = natural, varied follow-ups.

4

Final Report (temp 0.4)

All Q&A + scores → model produces verdict (Strong Hire / Hire / Maybe / No Hire) with summary and recommendations.

Embedding Model

How Embeddings Work

TalentLens uses BAAI/bge-base-en-v1.5 to convert resumes into 768-dimensional vectors stored in PostgreSQL with pgvector.

What is a Vector Embedding?

An embedding model converts text into a list of numbers (a vector) that captures semantic meaning. Similar meanings → similar vectors → close in space.

BAAI/bge-base-en produces 768 numbers for any text. TalentLens stores these in PostgreSQL with the pgvector extension.

How TalentLens Stores Embeddings
-- PostgreSQL schema with pgvector
CREATE TABLE resumes (
  id        UUID,
  raw_text  TEXT,
  parsed_data JSONB,
  embedding vector(768),   ← 768 floats per resume
  filename  VARCHAR
);

-- HNSW index for fast similarity search
CREATE INDEX ON resumes
  USING hnsw (embedding vector_cosine_ops);

-- Find top-5 similar resumes
SELECT raw_text,
       1 - (embedding <=> $1::vector) AS similarity
FROM resumes
ORDER BY embedding <=> $1::vector
LIMIT 5;

Actual API Call — Question Generation
// interviewerService.js
const res = await fetch('https://router.huggingface.co/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${process.env.HF_API_TOKEN}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    model: 'meta-llama/Llama-3.1-8B-Instruct:cerebras', ← from HF_GENERAL_MODEL
    messages: [
      { role: 'system', content: systemPrompt },  ← resume + rules
      { role: 'user',   content: 'Generate question 3.' }
    ],
    max_tokens: 150,
    temperature: 0.55,
  }),
});

const { choices } = await res.json();
const question = choices[0].message.content.trim();
